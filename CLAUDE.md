# VirtualUni

Multi-tenant SaaS educational platform. React/Vite/TS frontend + NestJS/Prisma/PostgreSQL backend, one instance serving many institutions (tenants) with row-level tenant isolation.

## Structure

- `src/` — frontend (React 18, Vite, TypeScript, Tailwind, Zustand, react-hook-form + Zod, react-router-dom).
- `backend/src/` — NestJS API. Modules under `backend/src/modules/<name>/`, each with `*.controller.ts`, `*.service.ts`, `dto/`, `*.spec.ts`.
- `backend/prisma/` — schema and migrations. **Never hand-edit files under `backend/prisma/migrations/`** — they're generated by `prisma migrate dev`/`migrate deploy`; a PreToolUse hook blocks this, but don't route around it. Add a new migration instead.
- `backend/src/common/guards/` — `JwtAuthGuard`, `RolesGuard`, `TenantGuard`. Every non-public controller should apply all three.

## Commands

Frontend (repo root): `npm run dev`, `npm run build` (runs `tsc --noEmit` first), `npm run lint`, `npx vitest run`.

Backend (`backend/`): `npm run start:dev`, `npm run build`, `npm run lint`, `npx jest`, `npx prisma migrate dev`, `npx prisma studio`.

## The most-repeated bug class in this codebase

Tenant/ownership checks missing or bypassable on client-controlled ids — confirmed 10+ times across billing, uploads, teachers, course-topics, attendance, payroll, materials, procedures (August 2026 audit). Before writing or editing any controller/service in `backend/src/modules/`:
- Every `update`/`remove`/`delete` by `id` needs a `findFirst({ where: { id, tenantId } })` (or equivalent) check *before* mutating — not just `where: { id }`.
- Every DTO field ending in `Id` must be validated against the caller's own tenant/enrollment before being trusted.
- If spreading a client-supplied object into a Prisma `where`, set `tenantId` *after* the spread.

The `tenant-isolation-reviewer` subagent (`.claude/agents/tenant-isolation-reviewer.md`) checks exactly this — use it after touching any backend module. Reference implementations for the correct pattern: `finance.service.ts`'s `assertOwnership()`, `messages.service.ts`'s `asegurarParticipante()`.

## Payments: Wompi, not Stripe

`backend/src/modules/billing/` integrates Wompi (Colombian gateway, COP), not Stripe — there is no Stripe SDK in this project. Wompi has no native recurring subscriptions: a tenant pays one period per checkout; renewal is a fresh checkout link, not an automatic charge. See `.claude/skills/billing-regression-check/SKILL.md` before editing this module — it documents a real checksum-verification bug that was silently wrong while its own test still passed.

## Legal pages have placeholders

`src/pages/PoliticaPrivacidad.tsx` and `src/pages/TerminosServicio.tsx` contain `[ENTRE CORCHETES]` placeholders for real company data (legal name, NIT, address, contact email) — don't invent real values for these; leave the placeholders until the user supplies actual company data.

## Known environment gotcha (Windows/Docker Desktop)

Docker Desktop's WSL2 backend can corrupt Postgres auth packets on docker-compose's custom bridge networks. If `prisma migrate`/`prisma generate` fails with a P1000 auth error against a compose-managed Postgres container, try a standalone `docker run` on a fresh port on the default bridge network instead of debugging the compose network further.

## Testing

Backend: Jest, `backend/**/*.spec.ts`, `testEnvironment: node`. Frontend: Vitest + Testing Library, `src/**/*.{test,spec}.{ts,tsx}`, jsdom — note `element.offsetParent` is always `null` under jsdom (no real layout), so don't write logic that depends on it without a jsdom-safe alternative.

## Deployment

Image-based Docker deployment (topology A): CI builds and pushes `virtualuni-backend`/`virtualuni-frontend` images; `docker-compose.yml` on the server pulls and runs them (`image:` references `${DOCKER_USERNAME}`, not `build:`). `scripts/deploy.sh` does `docker-compose pull && docker-compose up -d` — don't reintroduce `--build` there, it defeats the point of pre-built images.
